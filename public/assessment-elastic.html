Assessment: Elasticsearch MCP server

Leslie Kadenge · a public server I didn't write, read against the two-tier method

Elastic's MCP server is the only one in this collection written in Rust, and it wears that well: tool annotations are declared inline through a clean macro, and memory-safety-class bugs are off the table by construction. It's a focused, tidy server — and the one place I'd push is depth of testing, which I'll say plainly because a generous review isn't a silent one. Verifiable read.

The standout

The standout is how naturally the annotations sit in the code. Each tool declares its hints inline via a Rust macro — annotations(title = …, read_only_hint = true) right on the tool — so the read tools (list indices, get mappings, search) are marked read-only at the point of definition, hard to forget and easy to audit. Rust also takes an entire class of memory-safety bugs off the table that a review would otherwise have to consider.

Verdict

Clean and well-built where it counts — annotations at the point of definition, and a language that eliminates a whole bug class. The candid part, because a real review says it: test depth is the thinnest in this collection, and the write paths in particular deserve tests that pin them. Sound in design; the hardening to add is coverage and per-action confirmation.
