Assessment: Grafana MCP server

Leslie Kadenge · a public server I didn't write, read against the two-tier method

Grafana's MCP server, written in Go, has the cleanest take on read-only I've seen: turning it on doesn't just refuse writes, it removes the write tools from the list altogether — and the code says out loud that it's meant for deployments whose datasource credentials are themselves read-only. Guardrail and credential pointing the same way. Generous, verifiable read.

The standout

The standout is the disable-by-category design. Tools are grouped, and a deployment can switch whole categories off; read-only mode removes the write and query-write tools entirely rather than leaving them present-but-refusing. The comment in main.go is the tell: read-only mode is intended to pair with datasource credentials that are already read-only — so the server-side guard and the database-side permission agree, which is textbook defense in depth. Tools are annotated, and CI is heavy (11 workflows).

Verdict

A model for the access tier: removing write tools rather than merely refusing them, and explicitly designing the guard to sit on top of read-only credentials, is defense in depth done properly. The tier-two item left is per-action confirmation when writes are enabled. Sound on the basics, ahead on the access model and defense in depth.
